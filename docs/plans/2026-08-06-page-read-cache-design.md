# 页面只读查询缓存设计

## 目标

把首页、技能目录和技能包提交页的飞书读取结果在单个 Node 进程内缓存 60 秒，让缓存命中请求不再等待飞书 API，同时保持所有提交、取得、附议、认领和同步写操作实时执行。

## 方案

新增页面只读查询层，公开 `listSkillEntries` 和 `listWishes` 两个查询。它缓存未筛选的完整视图，页面的职能和关键词筛选在缓存结果上执行，因此不同筛选条件共享同一份飞书结果。缓存项保存进行中的 Promise，使同一时刻到达的请求合并成一次读取；读取失败立即删除缓存项，下一次请求仍会访问飞书并继续沿用现有有限退避和页面降级逻辑。

页面只读查询层只被 React 页面使用。API Route 和其他写流程继续直接使用 `deps()`，不会读取页面缓存。缓存驻留在 `globalThis`，避免 Next.js 开发期模块重载丢失，并与当前依赖容器的生命周期保持一致。

飞书列记录请求继续使用单页上限 500，避免全量分页时产生更多网络往返；通过官方支持的 `field_names` 参数按表限定领域转换所需字段，减少响应体。首页已有两组查询并发，技能目录内部的技能包表和条目表也已并发，无需改变。

## 错误与测试

保留 `1254607 Data not ready` 的两次有限退避。重试最终失败时，失败不会进入缓存；首页继续部分降级，提交页继续显示可提交表单和友好提示。

测试以两个公共边界为准：页面只读查询接口覆盖 60 秒复用、并发合并和失败不缓存；页面组件测试继续覆盖飞书不可用时的降级渲染。飞书适配器测试补充各表请求只包含所需字段。
