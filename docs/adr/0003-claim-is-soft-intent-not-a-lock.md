# 认领是软意向，不是排他锁

一条许愿可以被多人同时认领，页面展示"N 人在做"。没有排他锁、没有超时释放。许愿的完成状态**不由认领决定**，而由"是否有 Skill 关联到它"决定 —— 认领与交付是两件解耦的事。

反直觉，所以记下来：下一个人看到这个模型，第一反应会是"这里缺一把锁，我来补上"。别补。锁在这里行不通，也不需要：

- 本项目无登录（见 [ADR-0001](./0001-no-feishu-login-cross-tenant.md)），锁只能锁给一个自填昵称，本质上锁不住。
- 这是志愿社群，认领的真实含义是"我有空想试试"，不是工作分配。给它排他性只会长出僵尸认领：占着位、没人交、别人不敢动。
- 重复实现在社群里不是浪费 —— 多个版本可比，反而是好事。

参照 HRAS AI 岛的「开放认领」：那是准工作分配，背后有雇主、AI 应用小组排期、大赛激励和奖金兜底。本项目一样都没有，所以不能照搬它的认领语义。
