# 群通道只用自定义机器人 webhook，不监听群消息

飞书群通道只做**出站推送**，用群自定义机器人 webhook。明确**不做**监听群聊、用 AI 从对话里自动识别痛点生成候选许愿。

自定义机器人 webhook 只能发不能收。要监听群消息必须建自建应用并订阅 `im.message.receive_v1`，还要处理外部群的消息可见性与权限限制，以及"未经告知就分析群友对话"的隐私问题。收益（少量候选许愿）远低于这三项成本。

已确认的三类联动全部与 webhook 兼容，不需要自建应用：

1. 许愿池 ↔ 技能目录互相导流（纯前端 + 一个关联字段）
2. 定期扒 GitHub / skills.sh 热榜推群（定时任务 + webhook）
3. 许愿附议数过阈值后自动升级为「待认领任务」并推群招人（对应 HRAS 那个「开放认领」位置，也是让附议排序真正产生作用的机制）

第 3 条是把 [ADR-0003](./0003-claim-is-soft-intent-not-a-lock.md) 的软意向模型和附议排序接起来的关键 —— 排序不只是展示顺序，它触发一次真实的招募动作。
