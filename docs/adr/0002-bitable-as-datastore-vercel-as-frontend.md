# 飞书多维表格作数据存储，Vercel 网页作前台

数据（Skill 目录、许愿、认领）存在飞书多维表格，前台是部署在 Vercel 上的网页；网页同时提供统一的取得出口并把取得数回写多维表格。

选它不是因为技术上更干净（自建 Postgres 更干净），而是为了**把运营权交回社群**：王倩和运营同学可以直接在多维表格里改数据、加字段、建视图，不必每次找开发。社群主动机是"把模块分给大家"，单点依赖某一个开发者与这个目标冲突。Vercel 免费额度也避免占用社群的服务器资源。

代价：schema 受多维表格字段类型限制，写入有 API 频率限制，复杂查询要在前台兜。取得数计数因此是"最终一致"的，不保证实时精确。

社群后续会提供服务器、域名与公网 IP。届时前台可迁到自有服务器（Docker + 域名），数据层不变 —— 迁移成本低，因此不必为了等这批资源推迟第一版上线。注意公网 IP 与域名不改变 [ADR-0001](./0001-no-feishu-login-cross-tenant.md) 的结论：可访问性与身份验证是两个问题。
