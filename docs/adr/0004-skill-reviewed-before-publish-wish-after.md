# Skill 先审后发，许愿与附议先发后审

Skill 必须人工过一道审核才对外可见；许愿和附议直接可见，事后抽查与举报下架。

分层的依据是**可撤回性**，不是重要性：Skill 是文件包，一旦被人取得就无法召回，事后下架只能阻止新用户，删不掉已有副本 —— 所以只有事前审核有效。许愿是纯文本，改和删都还有效，先发后审的风险可控，而给许愿加审核队列会直接掐死冷启动期的参与量。

这道审核挡的是本项目特有的风险：HR NEXT 是**跨公司**社群。群友上传的 HR skill 很容易夹带雇主资产（真实薪酬结构与带宽、花名册字段、绩效评级分布、内部审批流程、真实员工数据样例）。同一份材料在 Serena 公司的 HRAS AI 岛内部流通是合规的，流到 HR NEXT 就是跨公司泄露雇主机密，上传者本人可能担责，社群会被连带。这是 HRAS 不存在、本项目必须处理的约束。

配套：上传时强制勾选脱敏声明（不含真实员工数据、薪酬明细及所属公司未公开资料）。声明不替代审核，只是把责任意识前置。

审核成本在第一版接近于零 —— HRAS 运行至今也只有 10 个技能，量级很小。
