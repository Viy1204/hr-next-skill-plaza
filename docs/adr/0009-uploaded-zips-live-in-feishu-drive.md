# 自助上传的 zip 存在飞书云空间，不公开、不落服务器

平台此前只存链接：技能包指向作者的 GitHub 仓库，站点本身不托管任何可执行内容，出事也是 GitHub 的事。现在接受自助上传 zip，这条边界主动放弃了，值得留档。

**放在哪**：飞书云空间，跟多维表格同一个租户。不落服务器磁盘 —— 那台机器在开发者名下（[ADR-0008](./0008-deploy-on-the-community-server-not-vercel.md)），文件长在上面会让搬家时多一份要迁的状态，而云空间的归属跟数据一致，将来一起转给社群。也不进对象存储：多一个账号、多一份账单、多一套密钥，这个体量不值得。

**不公开**：文件不设公共链接。取得时由 `/get` 出口用应用身份把文件取回来转给访客，所以**待审的技能包下载不到** —— 审核那道闸（[ADR-0004](./0004-skill-reviewed-before-publish-wish-after.md)）对附件同样成立。如果改成公开分享链接，任何人拿到 URL 就能在审核前下载，闸门形同虚设。

代价是每次下载都过一遍服务器。文件上限 20MB，转发是流式的，不在内存里攒整个文件 —— 那台机器只有五百多兆可用内存。

**运营怎么审**：上传后应用会把文件的查看权限授给运营（`FEISHU_REVIEWER_OPEN_ID`），文件出现在他云空间的「共享给我」里。不这么做的话文件只在应用自己的空间里，运营根本打不开要审的那个 zip —— 审核就成了走过场。

**孤儿文件**：被拒的提交会在应用空间里留下文件。应用自己删不掉，但已验证的清理路径是：应用把文件**所有权转移**给运营 → 运营以自己的身份删除（协作者哪怕 full_access 也删不掉别人名下的文件，必须先转移所有权）。操作步骤写在运营手册「下架与清理孤儿文件」一节。20MB 上限加上社群体量，攒一批清一次即可，不做产品化的「拒绝并删附件」动作 —— 等真积压了再说。

**仍然优先 GitHub**。zip 是死的：作者改一版就得重新上传，很快会出现「站上这份是三个月前的」。GitHub 仓库自动指向最新。表单默认选 GitHub，zip 是给确实没有仓库的人留的后路。
