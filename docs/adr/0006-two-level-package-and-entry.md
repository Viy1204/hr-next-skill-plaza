# 技能目录分两级：技能包与技能条目

目录按**技能条目**展示、搜索、打标签；取得按钮与取得数挂在条目所属的**技能包**上。一个技能包含 1..N 个条目。

原因是"可取得的单元"和"一条能力"在现实里不是同一个东西：

- `Viy1204/hr-skills` 里 5 个技能各自独立，可以各自成包。
- `Viy1204/recruiting-copilot` 是整包插件 —— 7 个 slash command 共用一套安装脚本和工作区，**拆不开单独取得**。

只做条目级会逼着把整包插件拆成 7 个"单独取得都跑不起来"的条目，是造假；只做包级会把十几个能力压成两条，搜索和标签筛选失去意义，"技能排名"退化成"仓库排名"。

参照 skills.sh（Vercel）：它显示「19 sources 42 skills」，install 数记在 source 上而不是单个 skill 上 —— 同一个问题，同一个解法。

配套结论：取得数只在同级（包与包之间）可比，不可摊到条目上。把包的取得数摊给每个条目会误导排名 —— 没人会为了其中一个 command 去装整包。
