# 项目归属社群（群主名下），个人只留开发权限

飞书租户、多维表格、自建应用、域名、部署账号，长期全部建在群主（王倩）名下。demo 阶段可以先建在别处，但**不得建在任何参与者的雇主租户里** —— 要用一个专门的社群/测试飞书账号。

这条是踩过一次才补上的：第一次建表时 `lark-cli` 当时授权的身份是开发者的公司账号，Base 直接落在了雇主的云空间里。写进去的内容全是公开的 GitHub 仓库信息、没有任何公司数据，但归属本身就是问题：一个跨公司社群的数据根挂在某家公司的租户下，离职、权限收紧、合规检查任何一件事都能让社群断供。那个 Base 已删除。

**操作纪律**：任何往飞书写数据的动作之前，先跑 `lark-cli auth status` 确认身份，不要假设当前授权的是哪个账号。`scripts/setup-bitable.sh` 已内置这道确认。

这么定不是技术考虑，是**治理**考虑：社群的明确意图是把模块分给大家，参与者对投入时间的承诺是"尽量参与"。如果租户、密钥、审核权、账单全挂在某一个人名下，这个人就是单点，运维债会一直压在他身上直到项目停摆 —— 这是社群项目最常见的死法。所有权归社群，个人的退出成本才是可承受的。

代价：迁移要重建一次自建应用与多维表格（约半天）；开发者后续改动依赖社群侧给权限，响应速度不由自己控制。这是有意接受的代价。
