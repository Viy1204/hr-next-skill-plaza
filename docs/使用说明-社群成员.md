# 技能广场怎么用（社群成员）

https://viy1204.me —— 手机浏览器直接打开，**不用登录，不用注册**。

站里放两样东西：群友已经做出来的**技能包**，和大家还等着有人做的**许愿**。

---

## 一、找现成的能力

### 逛技能目录

点「技能目录」。列表按**取得数**排序，每一行是一个**技能条目**（一个具体能力，比如「实时拉取花名册并导出 Excel」）。

两种找法：

- **搜索框**：搜条目名称或说明里的词，比如「花名册」「考勤」「简历」
- **职能筛选**：按 HR 职能模块过滤 —— 招聘 / 组织与人才发展 / 薪酬福利 / 绩效 / 培训 / 员工关系 / HR 数据分析 / HR 运营与共享服务

两个可以叠着用。

### 看清楚再取

点条目名进详情页，**先看「前置条件」**。那里写的是你必须自备的东西，例如：

- 运行环境（如 Node 20 以上）
- 本机要装的浏览器
- 某个平台的登录态（如 Boss 直聘、猎聘要你自己扫码登录）
- API 凭证（如飞书自建应用的 app_id / app_secret）

**前置条件不满足，取回去大概率装不上、跑不起来。** 这是最常见的失败原因，不是技能包的问题。

### 取得

点「取得这个技能包」，会跳到作者的 GitHub 仓库或下载地址。

注意两件事：

- **取得永远发生在技能包上，不是单个条目上。** 有些技能包里装了好几个条目（比如招聘那套有 7 个），它们共用一套安装脚本和工作区，拆不开，只能整包拿走
- **取得数只代表「有人想试」** —— 不代表被使用过，更不代表在你的环境里跑得起来。它是个参考值，不是质量评分

## 二、提出你想要的能力

### 许愿

点「我要许愿」。只需要说清楚**你卡在哪**：

| 填什么 | 怎么填 |
|---|---|
| 一句话说清你想要什么 | 例：每月核对花名册要花一整天 |
| 痛点场景 | **谁**、在**什么时间**、进行**什么操作**、需**交付什么结果**。例：HRBP 每月初手工比对系统导出与本地台账，交付一份人员差异清单给业务负责人 |
| 适用职能 | 选一个 HR 职能模块 |
| 每月花多少小时（选填） | 只展示给可能来认领的人做判断，**不进任何排序公式**，填小了不会没人看 |
| 你的昵称（选填） | 留了名，有人想细聊时能在群里找到你 |

**不用想技术方案** —— 方案是认领人的事。描述得越具体，越容易有人接。

许愿提交后会自动推到 HR NEXT 群里。

### 附议：「这个痛点我也有」

在许愿详情页点「我也有这个痛点」。

**附议不是点赞**，不是「这想法不错」，而是「这件事同样卡着我」。许愿池按附议数排序，附议是唯一的排序依据 —— 你按的每一下都在决定谁先被做出来。

同一个人重复点不会重复计数。

**当一条许愿攒够 10 个附议**，它会自动升级为**待认领任务**并推到群里招人。这个阈值可以调，运营会看真实情况改。

### 认领：「我想试着做」

在许愿详情页点「我想试着做」，留个昵称，可以顺便说说打算怎么做。

- **认领不排他**。同一条许愿可以多个人同时认领，做出两个版本反而能互相比
- **认领不等于承诺**。做不完不用有压力，也不会有人来催
- **认领不等于交付**。一条许愿只有在真的有技能包关联上去之后，才算被满足

## 三、几个说明

**不用登录，所以也别把它当权威数据。** 取得数和附议数在没有登录的情况下都是可以刷的参考值，**不得作为任何激励、奖金或评选的依据**。它们的用途只有一个：帮大家决定先做什么、先试什么。

**你的痕迹很少。** 站点不接飞书登录（成员分属不同公司、不同租户，登录这件事在跨租户下不成立），昵称是选填的，不填就是匿名。

**群里的旧链接可能会失效。** 许愿或技能包被下架后，旧消息里的链接会显示「这个页面不在了」—— 是内容没了，不是你点错。

**发现问题、想上架自己的技能包**，直接在 HR NEXT 群里说。目前上架由运营手工录入，还没有自助上传。
